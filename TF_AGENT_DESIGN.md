# Testing Farm suite agent

The `/analyze/tft` route accepts one entire suite, regardless of guest count, with case IDs, a safe `guests` map, and published log references. It durably admits a `tft_suite` task and returns 202 with a fixed `deadlineAt`; the existing task polling and cancellation routes apply. This is an unreleased implementation with no legacy task compatibility requirement. The gluetool integration is deferred.

The worker caches successful and failed URLs under the 50 MiB aggregate budget and namespaces artifacts as `shared/<name>` or `case/<case_id>/<name>`. Partial retrieval failures produce scoped warnings; cases with any own or shared evidence remain eligible, and evidence-less cases receive a safe `artifact_error`. Drain extraction runs once before one BeeAI agent run over all submitted case and guest context, avoiding a tool turn per log. A separate eligible-case-ID list restricts diagnoses to cases with usable evidence without dropping unavailable cases' notes, checks, results, or guest associations. Testing Farm omits snippet annotation but retains optional extraction and historical lookup. Its structured output is validated against eligible case IDs and extracted, owned evidence. Per-case diagnoses use the established explanation, solution, no_issue_found, and snippets fields. A zero-case suite failure receives one context-only fallback. The system prompt retains conditional GitLab.com HTTP-429 advice about bundling files or using an available mirror.

The worker publishes the complete result in one fenced task transition. A missing/empty case diagnosis is a per-case error; duplicate/unknown IDs or invalid evidence references fail the task. Inference failure, timeout, and cancellation remain task-level outcomes. The fixed 600-second default budget includes queue time, downloads, extraction, inference, and retries; reconciliation expires queued suites. Blocking cleanup may delay terminal reporting. One agent run does not imply one provider request.

Testing and documentation for the server contract live in `tests/test_tft.py`, `docs/api.md`, and `docs/agent-tools.md`. The follow-up gluetool change will use its existing per-suite hook, map by `case_id`, preserve cached analyses, and wait up to 600 seconds. No gluetool code changes belong to this phase.
